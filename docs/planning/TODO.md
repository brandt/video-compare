- BUG: "Window exceeds display area" warning fired spuriously on macOS Retina displays. Root cause was unit-mismatch plus bad chrome estimates: `SDL_GetDisplayUsableBounds` and `SDL_GetWindowSize` both return *points* on HiDPI, but the subtracted chrome constants (`border_width=10`, `border_height=34`) were tuned for X11/Windows pixels. macOS windows have no side chrome (0 pts) and a ~28-pt titlebar, so a legitimately-fitting window at exactly the usable width fired the warning. Switched the fallback constants to `__APPLE__`-specific values (0/28), and the check now prefers `SDL_GetWindowBordersSize` when the platform actually reports it (Windows, some X11). macOS returns `have_frame=0` so the fallback still drives the comparison — now correctly.

- FEATURE: Auto-align L2-seek precision. Three compounding bugs made the 3-press forward alignment miss the target frame by up to ~180 ms on the lg-daylight pair: (1) window extension used `prefetch_size()` (dynamic count) instead of `prefetch_capacity()`, so after a fresh L2 seek the extension collapsed and truncated the walk before the true-alignment candidate was decoded; (2) `drain_to_target` was disabled under `pure_right_frame_shift` for `+`/`-` responsiveness, but auto-align's shift routes through the same flag and got the same skip, so the L2 drain landed wherever the first popped frame happened to be — fixed by OR-ing `pending_auto_align_verification_.active`; (3) the tie-break band of 0.002 let a near-peak candidate beat the true 1.000 peak when it was closer to current — tightened to 0.0005. Plus the `TimeShifter::set_static_shift_us` override now runs regardless of post-seek verification probe count, using the actual landed pts as ground truth rather than `total_frames × avg_delta` (which drifts on variable-duration encodes like 59.94 fps VP9 with 16/17 ms alternating deltas). The 3-press test now converges to the target frame exactly (within 2 ms).
